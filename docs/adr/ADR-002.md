# Login and user session in the frontend

**Status:** Approved

**Context:** Users need to log in, and the frontend needs to know who is using it and if they are a student or staff (staff get the manage page, students only request slots).

**Decision:** The login page sends login, password and role (the tab picked, student or staff) to the backend `POST /login`, and the backend answers if they are valid. We only keep login, name and role in localStorage so a refresh doesn't log the user out. The password is never saved anywhere in the frontend, it is only sent once.

**Alternatives:** We could also keep the password in localStorage to log in again automatically. But it is the user's SDU password, and anything in the browser storage can be read by anyone using that computer or by a script on the page. We could also keep nothing and make the user log in on every refresh, which is safer but annoying to use.

**Consequences:** The password is never stored, but the saved user (including the role) can be edited by hand in the browser, and the backend doesn't give a token or session, so nothing else checks who is calling. For now the role only decides what the UI shows. The user stays logged in until they press logout. If the backend is down nobody can sign in.
